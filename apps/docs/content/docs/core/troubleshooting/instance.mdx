## My Nomploy UI Instance is Not Accessible

If you can't access your Nomploy UI instance, there could be several causes. While this issue won't occur with Nomploy Cloud (where our team manages the infrastructure), self-hosted instances might encounter configuration problems.

Let's go through the possible cases where your Nomploy UI instance might be inaccessible:

### 1. Insufficient Storage Space

If you've made many deployments and don't have available space on your server, the Nomploy database might enter recovery mode, preventing access to the user interface. Here's a quick solution to clear cache and free up server space:

```bash
docker system prune -a
docker builder prune -a
docker image prune -a
```

### 2. Container Race Condition During Restart

During a restart, a race condition might occur where Nomploy's dependent containers don't start in the correct order. To troubleshoot this:

First, verify the running containers:
```bash
docker ps
```

You should see all three of these containers running:
```bash
2a5b955c32b6   nomploy/nomploy:latest      "docker-entrypoint.s…"   4 days ago     Up 4 days     0.0.0.0:3000->3000/tcp, :::3000->3000/tcp                                                                             nomploy.1.4bkuszk98muz372kw5mvwkw0h
5a989bf52bc6   postgres:16                 "docker-entrypoint.s…"   4 days ago     Up 4 days     5432/tcp                                                                                                              nomploy-postgres.1.9hvjaxrmby7ex2denjtwo0csf
05be01c5612f   traefik:v2.5                "/entrypoint.sh trae…"   4 days ago     Up 4 days     0.0.0.0:80->80/tcp, :::80->80/tcp, 0.0.0.0:443->443/tcp, :::443->443/tcp, 0.0.0.0:8080->8080/tcp, :::8080->8080/tcp   nomploy-traefik.1.2oktabjmfu558x2d2dy6czt8m
```

<Callout type='info'>
  **Note:** If you're running a version older than v0.29.9, you'll also see a `nomploy-redis` container. Redis is no longer used in self-hosted Nomploy since v0.29.9.
</Callout>

If all three containers are running but you still can't access the interface, it's time to debug:

### Debugging Process

#### 1. Check Container Logs
Start by examining the logs of each container:

```bash
docker service logs nomploy # Nomploy UI
docker service logs nomploy-postgres # Postgres
docker logs nomploy-traefik # Traefik
```

#### 2. Common Database Connection Issue

A common case is when the Postgres container starts after the Nomploy container, preventing Nomploy from connecting to the database. You might see logs like this when running `docker service logs nomploy`:

```ts
> nomploy@v0.22.3 start /app
> node -r dotenv/config dist/server.mjs

Default middlewares already exists
Network is already initilized
Main config already exists
Default traefik config already exists
Migration failed [Error: getaddrinfo ENOTFOUND nomploy-postgres] {
  errno: -3008,
  code: 'ENOTFOUND',
  syscall: 'getaddrinfo',
  hostname: 'nomploy-postgres'
}
Setting up cron jobs....
Main Server Error [Error: getaddrinfo ENOTFOUND nomploy-postgres] {
  errno: -3008,
  code: 'ENOTFOUND',
  syscall: 'getaddrinfo',
  hostname: 'nomploy-postgres'
}
```

To fix this, restart the Nomploy service:
```bash
docker service scale nomploy=0
# Then
docker service scale nomploy=1
```

#### 3. Traefik Configuration Issues

If all containers are running but you still can't access the UI, and Nomploy logs show no errors, the Traefik container might have configuration issues.

When running `docker logs nomploy-traefik`, you might see errors like:

```shell
2025-04-07T15:20:18Z ERR Error occurred during watcher callback error="/etc/nomploy/traefik/dynamic/nomploy.yml: field not found, node: passHostHeader" providerName=file
```

First, try restarting Traefik:
```bash
docker restart nomploy-traefik
```

If you still can't access it and the same error persists in the Traefik logs, you'll need to check the Traefik configuration. In this case, the error indicates that the `passHostHeader` field is missing in the configuration.

If you've modified any Traefik configuration for an `application` and added invalid configuration, the logs will point to the error. For example, the error above mentions `field not found, node: passHostHeader`, which means we need to manually modify the configuration files in `/etc/nomploy/traefik`.

Here's an example of an invalid configuration:

```yaml
http:
  routers:
    nomploy-router-app:
      rule: Host(`my-domain.com`)
      service: nomploy-service-app
      entryPoints:
        - web
      middlewares:
        - redirect-to-https
    nomploy-router-app-secure:
      rule: Host(`my-domain.com`)
      service: nomploy-service-app
      entryPoints:
        - websecure
      tls:
        certResolver: letsencrypt
  services:
    nomploy-service-app:
      loadBalancer:
        servers:
          - url: http://nomploy:3000
          - passHostHeader: true
```

The correct configuration should be:

```yaml
http:
  routers:
    nomploy-router-app:
      rule: Host(`my-domain.com`)
      service: nomploy-service-app
      entryPoints:
        - web
      middlewares:
        - redirect-to-https
    nomploy-router-app-secure:
      rule: Host(`my-domain.com`)
      service: nomploy-service-app
      entryPoints:
        - websecure
      tls:
        certResolver: letsencrypt
  services:
    nomploy-service-app:
      loadBalancer:
        servers:
          - url: http://nomploy:3000
        passHostHeader: true
```

After fixing the configuration, restart Traefik:
```bash
docker restart nomploy-traefik
```

You should now be able to access the user interface.


## Recreate nomploy containers

In the case you want to recreate the nomploy services, you can do the following:

<Callout type='warn'>
  **Important:** Before recreating services, make sure you have backups of your data. Recreating services will not delete your volumes, but it's always good to have backups.
</Callout>

### Recreate Postgres Service

Remove and recreate the nomploy-postgres service:

```bash
docker service rm nomploy-postgres

# Create a new nomploy-postgres service with Docker Secrets
docker service create \
  --name nomploy-postgres \
  --constraint 'node.role==manager' \
  --network nomploy-network \
  --env POSTGRES_USER=nomploy \
  --env POSTGRES_DB=nomploy \
  --secret source=nomploy_postgres_password,target=/run/secrets/postgres_password \
  --env POSTGRES_PASSWORD_FILE=/run/secrets/postgres_password \
  --mount type=volume,source=nomploy-postgres,target=/var/lib/postgresql/data \
  postgres:16
```

<Callout type='info'>
  **Note:** Using Docker Secrets is the recommended approach for managing sensitive data like passwords. The secret is encrypted and only available to services that have been granted access to it.
</Callout>


### Recreate Traefik Service

Remove the nomploy-traefik service:

```bash
# If you are using docker standalone traefik
docker rm -f nomploy-traefik

docker run -d \
    --name nomploy-traefik \
    --restart always \
    -v /etc/nomploy/traefik/traefik.yml:/etc/traefik/traefik.yml \
    -v /etc/nomploy/traefik/dynamic:/etc/nomploy/traefik/dynamic \
    -v /var/run/docker.sock:/var/run/docker.sock:ro \
    -p 80:80/tcp \
    -p 443:443/tcp \
    -p 443:443/udp \
    traefik:v3.6.7

docker network connect nomploy-network nomploy-traefik

# If you are using docker service traefik
docker service rm nomploy-traefik

# Create a new nomploy-traefik service
docker service create \
  --name nomploy-traefik \
  --constraint 'node.role==manager' \
  --network nomploy-network \
  --mount type=bind,source=/etc/nomploy/traefik/traefik.yml,target=/etc/traefik/traefik.yml \
  --mount type=bind,source=/etc/nomploy/traefik/dynamic,target=/etc/nomploy/traefik/dynamic \
  --mount type=bind,source=/var/run/docker.sock,target=/var/run/docker.sock \
  --publish mode=host,published=443,target=443 \
  --publish mode=host,published=80,target=80 \
  --publish mode=host,published=443,target=443,protocol=udp \
  traefik:v3.6.7
```

### Recreate Nomploy Service

Remove and recreate the nomploy service:

<Callout type='info'>
  If the `nomploy_auth_secret` secret doesn't exist on your server (installations older than v0.29.3), create it first: `openssl rand -hex 32 | docker secret create nomploy_auth_secret -`
</Callout>

```bash
docker service rm nomploy

# Create the nomploy service
docker service create \
  --name nomploy \
  --replicas 1 \
  --network nomploy-network \
  --mount type=bind,source=/var/run/docker.sock,target=/var/run/docker.sock \
  --mount type=bind,source=/etc/nomploy,target=/etc/nomploy \
  --mount type=volume,source=nomploy,target=/root/.docker \
  --secret source=nomploy_postgres_password,target=/run/secrets/postgres_password \
  --secret source=nomploy_auth_secret,target=/run/secrets/nomploy_auth_secret \
  --publish published=3000,target=3000,mode=host \
  --update-parallelism 1 \
  --update-order stop-first \
  --constraint 'node.role == manager' \
  -e POSTGRES_PASSWORD_FILE=/run/secrets/postgres_password \
  -e BETTER_AUTH_SECRET_FILE=/run/secrets/nomploy_auth_secret \
  nomploy/nomploy:latest
```

**For Proxmox LXC environments**, add the `--endpoint-mode dnsrr` flag to all services:

```bash
docker service create \
  --name nomploy \
  --replicas 1 \
  --network nomploy-network \
  --mount type=bind,source=/var/run/docker.sock,target=/var/run/docker.sock \
  --mount type=bind,source=/etc/nomploy,target=/etc/nomploy \
  --mount type=volume,source=nomploy,target=/root/.docker \
  --secret source=nomploy_postgres_password,target=/run/secrets/postgres_password \
  --secret source=nomploy_auth_secret,target=/run/secrets/nomploy_auth_secret \
  --publish published=3000,target=3000,mode=host \
  --update-parallelism 1 \
  --update-order stop-first \
  --constraint 'node.role == manager' \
  --endpoint-mode dnsrr \
  -e POSTGRES_PASSWORD_FILE=/run/secrets/postgres_password \
  -e BETTER_AUTH_SECRET_FILE=/run/secrets/nomploy_auth_secret \
  nomploy/nomploy:latest
```



### Final Notes

While the specific issues may vary, the general troubleshooting approach remains similar to what we've described above, and is the general way we always follow when correcting a problem related to the nomploy instance not starting.. If you still can't access the user interface:
1. Check that all containers are running properly
2. Review the logs of each container for specific error messages
3. Verify all configuration files
4. Make sure to read the Traefik documentation for detailed configuration options: https://doc.traefik.io/traefik/
